# Level 0 semantics: findings from public sources

Research notes answering the Level 0 entries of
[open-questions.md](../open-questions.md#language) from public sources only.
The first recordings (B4J 10.70, OpenJDK 19, Windows 10) confirm the
behaviour behind the tests marked `status = "recorded"` in
`tests/conformance`; everything else here is still unconfirmed. Conformance
tests stay `pending-recording` until `tools/recorder` runs them on the
original toolchain; a recording always overrides what is written here.

October 2026.

## Findings

### Number-to-string conversion (source)

[`BA.NumberToString`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L415-L434):

- `Int`, `Long` (and so `Byte`, `Short`): `String.valueOf`, i.e. plain decimal.
- `Double`: Java `Double.toString(value)`, then a trailing `.0` is removed.
  So `3.0` → `3`, `2.7` → `2.7`, `1e20` → `1.0E20` (the `.0` before `E` stays),
  `0.0001` → `1.0E-4`, `1e7` → `1.0E7`, `NaN` → `NaN`, `-0.0` → `-0`.
- `Float`: widened to `double` first, so `1.1` as `Float` → `1.100000023841858`.
- Java's `Double.toString` algorithm changed in JDK 19 (shortest decimal that
  round-trips, JDK-4511638). B4J's install page recommends OpenJDK 19
  ([b4j.html](https://www.b4x.com/b4j.html)), so JDK ≥ 19 behaviour is the
  target. Rule recap: scientific notation when |x| < 1e-3 or |x| ≥ 1e7,
  otherwise plain decimal with at least one fractional digit.
- The compiler converts a number operand of `&` with `NumberToString`, and
  any other value with `ObjectToString` (**generated**):
  `"State changed: " & NewState` compiles to
  `"State changed: "+BA.NumberToString(_newstate)`, and
  `"error: " & LastException` to `"error: "+BA.ObjectToString(...)`.
  That `Log(number)` and number-to-String assignments do the same is still
  **forum** level.

Other values go through [`BA.ObjectToString`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L511-L513)
= `String.valueOf`, so Booleans print `true` / `false` (lower case) and `Null`
prints `null`. `Log(Null)` prints `null` ([`BA.Log`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L369-L371));
`Log` writes to stdout with a trailing newline.

An uninitialised `List`/`Map` prints as `(List) Not initialized` /
`(Map) Not initialized` (the `@ShortName`), and an initialised one as `(ArrayList) [1, 2]` / `(MyMap) {a=1}`
([`AbsObjectWrapper.toString`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/AbsObjectWrapper.java#L104-L130)).
Exact type names need a recording.

### Java-exact numbers (source, measured)

Checked bit for bit against OpenJDK 21.0.12 (fixtures in
`crates/interp/tests/data`, generated by running Java, and the
`level0/java_exact_numbers` test):

- `Double.toString` / `Float.toString` (JDK ≥ 19): of the shortest decimals
  that round-trip, the closest; of two equally close, the one with an even
  last digit. A `Float` widened to `double` is often such a tie:
  `27.899368` as Float prints `27.899368286132812`.
- `NumberFormat` and `NumberFormat2` each set up, on every call, their own
  shared `java.text.NumberFormat.getInstance(Locale.US)`
  ([`Common.NumberFormat`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L125-L148)).
  `DecimalFormat` takes a double's digits from the JDK's older conversion,
  which differs from `Double.toString` in three places (**measured**):
  - integers from 2^53 to 2^63 keep all their digits but the last 0, 1 or 2,
    depending on the binary exponent: `NumberFormat(1234567890123456789, 0, 0)`
    is `1,234,567,890,123,456,770`;
  - an exact power of two gets the shortest decimal within a quarter of the
    gap above on both sides (`Double.toString` allows half the gap above):
    `NumberFormat(Power(2, 64), 0, 0)` is `18,446,744,073,709,552,000`;
  - subnormals and a few values above 2^63 get 16 or 17 digits where fewer
    round-trip. FerroBASIC does not reproduce this (`docs/deviations.md`, D3).
- `ASin`, `ACos`, `ATan` and `ATan2` call `Math.asin` etc., which on HotSpot
  are `StrictMath`'s fdlibm code (**measured**: 200,000 inputs, no
  difference). FerroBASIC uses the `libm` crate, a port of the same code,
  plus fdlibm's handling of `ATan2` when |y/x| > 2^60 and x < 0.
- The degree variants divide by π, then multiply by 180:
  `Math.asin(Value) / Math.PI * 180`
  ([`Common.ASinD`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L320-L358)).
  The order changes the last bit: `ASinD(0.001)` is `0.05729578906238321`.
- `Select` matches with [`BA.switchObjectToInt`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L514-L533)
  (see Statements): when the scrutinee holds a number, every case is cast to
  `Number` and compared by `doubleValue`, so an `Object` holding Int 1
  matches `Case 1.0`, and a String case raises `ClassCastException`; otherwise
  the scrutinee's `equals` is used, so a `Null` scrutinee raises
  `NullPointerException`.

### Smart strings (docs, forum, source)

- `$"..."$`, multi-line, no escaping of `"` inside (**docs**, booklet §4.10.4).
- Placeholder: `$[formatter]{ expr }`. Erel: the compiler turns
  `$"x is ${x}"$` into `"x is " & x`
  ([forum, Erel](https://www.b4x.com/android/forum/threads/50135/)), so an
  unformatted placeholder converts like `&` does (**forum**).
- Formatters are case-insensitive and lower-cased by the compiler
  ([`Common.SmartStringFormatter`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L791-L846), **source**):
  - empty → `ObjectToString`;
  - `date`, `time`, `datetime` → `DateTime` (not Level 0);
  - `xml` → escapes `"` `'` `<` `>` `&` as `&quot; &#39; &lt; &gt; &amp;`;
  - `N` or `N.M` → `NumberFormat(value, N, M)` (no `.M`: unlimited fractions),
    `NaN` if the value is not a number. `NumberFormat` is Java
    `NumberFormat.getInstance(Locale.US)` with grouping on, so
    `$1.2{12345.678}` → `12,345.68` ([`Common.NumberFormat`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L125-L131)).
    Java's default rounding mode for it is HALF_EVEN.
- **open**: how to write a literal `${` or `"$` inside a smart string.

### Map (source)

- `Initialize` creates a `MyMap` wrapping a `LinkedHashMap`: iteration over
  `Keys` / `Values` is in **insertion order**; re-putting an existing key keeps
  its position ([`Map.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/Map.java#L57-L59), [L225-L227](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/Map.java#L225-L227)).
- Keys compare with Java `equals`: string keys are case-sensitive, and boxed
  numbers of different types are different keys (`Int` 1 ≠ `Double` 1.0).
  Which boxed type a numeric literal key gets is compiler behaviour (**open**).
- `Put` returns the previous value or `Null`; `Get` of a missing key returns
  `Null`; `GetDefault` returns the default when the stored value is `Null`.
- `GetKeyAt` / `GetValueAt` go through `MyMap.getEntry`
  ([`Map.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/Map.java#L219-L248)), which keeps
  an iterator, the index it stands at and the entry it last returned. Every
  `Put`, `Remove` and `Clear` drops the iterator, but not that entry. So:
  - the next index moves the iterator on; any other index starts again and
    walks `index + 1` entries;
  - an index past the end raises `java.util.NoSuchElementException`, after
    walking every entry. The entry last returned is then the last one, and
    asking again for the index the iterator stood at returns it;
  - a negative index walks nothing and returns the entry last returned
    (its current value, or its last one if it was removed), or raises
    `NullPointerException` if there is none.

### List (source)

- `Initialize` creates a `java.util.ArrayList`. `Get`/`Set`/`RemoveAt` out of
  range throw Java `IndexOutOfBoundsException` (catchable with `Try`).
- `Sort` requires all numbers or all strings
  ([`List.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/List.java)).
- An array passed as a `List` goes through `Common.ArrayToList`
  ([`Common.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L715-L729)): a primitive
  array is boxed into a copy, any other array is wrapped by `Arrays.asList`.
  An array of rank 2 or more does not get there: the compiler casts it to
  `List` instead, which javac rejects (**recorded**, B4J 10.70: "int[][]
  cannot be converted to List"), so passing one where a `List` is expected
  is a compile error. Through an `Object` variable it is *(open)*.
- B4X arrays are Java arrays (jCore takes them as `int[]`, `Object[]`, …), so
  `Grid(i, j)` is Java's `grid[i][j]`, evaluated as the JLS says (§15.10.4,
  §15.26.1): `grid[i]` selects and checks the row before `j` is evaluated,
  and an assignment selects the row before it evaluates the value. This
  shows when evaluating `j` or the value replaces the row, and when the row
  index is out of range.
- `AddAll` / `AddAllAt` call Java's `addAll`
  ([`List.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/List.java#L97-L105)), which
  (**measured**, JDK 21) behaves by list class:
  - `ArrayList` checks the index, then adds; even adding nothing counts as a
    modification, so it invalidates the list's `SubList` views;
  - a fixed-size list (`Arrays.asList`) checks the index, then raises
    `UnsupportedOperationException` only if there is something to add;
  - a `SubList` view (`Collections.unmodifiableList`) always raises
    `UnsupportedOperationException`.
- The other changes through a `SubList` view (**measured**, JDK 21, test
  `list_stale_sublist`) are refused the same way, before the view is read:
  `Add`, `InsertAt`, `RemoveAt`, `Set`, `Clear`, and `Sort` and
  `SortCaseInsensitive` (`Collections.sort` calls the view's `sort`), even
  when the parent has changed since. `SortType` and
  `SortTypeCaseInsensitive` differ, following jCore's `sortList`
  ([`List.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/List.java#L203-L227)):
  it reads the size first (so a stale view raises
  `ConcurrentModificationException`), returns on an empty list, and looks
  up the field on the first item (`NullPointerException` for `Null`,
  `NoSuchFieldException` for a missing field) before the view refuses to
  sort.

### Built-in members (source, docs)

The members a program calls on a value are thin wrappers over Java, so
their behaviour is Java's. Checked by running the same calls on OpenJDK 21
(the `string_members`, `string_builder`, `list_members` and `map_members`
tests):

- **String** members are `java.lang.String`'s
  ([core reference, String](https://www.b4x.com/b4j/help/core.html#string),
  **docs**): `CharAt`, `IndexOf`, `SubString2` and `Length` count UTF-16
  code units; `CompareTo` returns the difference of the first differing code
  units, or of the lengths; `Replace` is literal, left to right; `Trim`
  removes code units up to U+0020 only; an index out of range raises
  `StringIndexOutOfBoundsException`. Case mapping is the open question on
  locales; outside Turkish, Azeri and Lithuanian it is the Unicode default
  (`"Straße".ToUpperCase` is `STRASSE`).
- **StringBuilder** wraps `java.lang.StringBuilder`
  ([`StringBuilderWrapper.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/StringBuilderWrapper.java)):
  `Append`, `Insert` and `Remove` return the wrapper, so calls chain;
  `Remove(Start, End)` is `delete`, which stops at the length when `End` is
  past it; an offset out of range raises `StringIndexOutOfBoundsException`.
- **List** ([`List.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/List.java)):
  `InsertAt`, `RemoveAt`, `Set` and `IndexOf` are `ArrayList`'s `add`,
  `remove`, `set` and `indexOf` (`equals`, so boxed types matter).
  `Sort(True)` is `Collections.sort`; `Sort(False)` sorts with the reversed
  comparison; `SortCaseInsensitive` compares the items' `toString()` with
  `compareToIgnoreCase`; `SortType` / `SortTypeCaseInsensitive` compare the
  named field the same ways, and return at once on an empty list. Every sort
  is `Collections.sort`, which is stable, also when descending.
- `SortType` / `SortTypeCaseInsensitive` take the field from the first item
  (`get(0).getClass().getDeclaredField`, so `Null` raises
  `NullPointerException` and a missing field `NoSuchFieldException`), then
  sort with a comparator that reads that field from every item with
  `Field.get` and wraps any exception in a `RuntimeException`
  ([`List.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/List.java#L203-L227)).
  **Measured** (JDK 21, test `list_sort_type_errors`): an item of another
  type, or a non-record, raises `RuntimeException` caused by
  `IllegalArgumentException`; a `Null` item or a `Null` field value, by
  `NullPointerException` (case-insensitively the field is
  `String.valueOf`'d, so `"null"`); field values that are not mutually
  `Comparable`, by `ClassCastException`. A list of one item is not compared.
  Which item raises first depends on the order `TimSort` compares in;
  FerroBASIC checks the items in list order, so in a list with several kinds
  of problem the wrapped cause can differ, never the `RuntimeException`
  (deviation D4). A `Catch` sees the cause, since `LastException` is the
  innermost cause (below; **recorded**, `list_sort_type_errors`). The
  comparator catches `Exception`, so an `Error` such as
  `StackOverflowError` (printing a field nested too deeply) is not wrapped.
  FerroBASIC also accepts the field `IsInitialized`, which the class of a
  `Type` is expected to have (its `toString` prints it first); measured
  only with a Java class of that shape, so it is an open question, like the
  fields of JDK classes (test `list_sort_type_class_fields`).
- A sort that raises (**measured**, JDK 21) leaves the list partly sorted:
  `ArrayList.sort` runs `TimSort` on the list's own array and stops at the
  failing comparison, so `[1, 3, 2, "x"]` is `[1, 2, 3, x]` after `Sort`
  raises. FerroBASIC checks every item first and leaves the list as it was
  (deviation D5).
- **Map** ([`Map.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/collections/Map.java)): `Remove`
  returns the removed value or `Null`; `GetDefault` returns the default when
  the key is missing or its value is `Null`; `ContainsKey` is
  `containsKey`, so a key with a `Null` value is present.

### Keywords, maths and Bit (source)

The keywords are static methods of [`Common.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java),
and `Bit` is [`Bit.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Bit.java); each is one Java call.
Checked on OpenJDK 21 (the `math_builtins`, `bit_functions`,
`chars_and_ints`, `random_seeded` and `exit_code` tests):

- `Abs`, `Sqrt`, `Ceil`, `Floor`, `Max`, `Min`, `Power` are `Math`'s, so
  `Max` and `Min` return NaN if either side is NaN, and order `-0` below `0`.
  `Logarithm(n, b)` is `Math.log(n) / Math.log(b)`. (`Power` and `Logarithm`
  on inexact values are an open question: CPU intrinsics.)
- `Round` is `Math.round`: halves go towards positive infinity (`Round(-2.5)`
  is `-2`), and NaN gives 0. `Round2(x, d)` is `Math.round(x * 10^d) / 10^d`,
  so `Round2(2.675, 2)` is `2.68` although 2.675 is just below it in binary.
- `cPI` and `cE` are `Math.PI` and `Math.E`. `CRLF` is a single line feed
  (`"\n"`), `TAB` is `"\t"` and `QUOTE` is `"`.
- `Asc` and `Chr` convert between a `char` and its UTF-16 code unit. `Not` is
  `!`.
- The `Bit` functions are Java's `int` operators: shift counts are taken
  modulo 32, and `ToHexString`, `ToBinaryString` and `ToOctalString` print a
  negative number as its 32-bit two's complement.
- `Rnd(Min, Max)` is `Min + random.nextInt(Max - Min)` on one
  `java.util.Random`, created with `RndSeed`'s seed (later calls reseed it) or
  unseeded on first use. So a seeded sequence is exact, and `Rnd(5, 5)`
  raises `IllegalArgumentException`.
- `ExitApplication` and `ExitApplication2(n)` are `System.exit`: the process
  ends at once with code 0 or `n`, and `Try` cannot catch it.
- Integer arithmetic follows Java: `Int` and `Long` wrap around, `Int * Int`
  is an `Int` even when stored in a `Long`, Byte and Short operands become
  `Int`, and `Mod` by an integer zero raises `ArithmeticException`.

### Number parsing (source, measured)

- `IsNumber(Text)` is `Double.parseDouble(Text)` without an exception
  ([`Common.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Common.java#L441-L448)): a `Null` text
  raises `NullPointerException`, which `IsNumber` does not catch.
- `Bit.ParseInt(Value, Radix)` is `Integer.parseInt(Value, Radix)`
  ([`Bit.java`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/keywords/Bit.java#L164-L166)), which reads each
  `char` with `Character.digit`: any Unicode decimal digit (Arabic-Indic,
  Devanagari, fullwidth, …) counts, and so do the fullwidth Latin letters
  for radixes above 10. Digits outside the Basic Multilingual Plane are two
  `char`s, neither a digit. FerroBASIC's table is checked against JDK 21
  (Unicode 15).

### Uninitialised objects (source)

Any member call on an uninitialised `List`/`Map` throws a `RuntimeException`
with the message `Object should first be initialized (List).` (or `(Map).`)
([`AbsObjectWrapper.getObject`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/AbsObjectWrapper.java#L41-L52)).
`IsInitialized` returns whether the wrapped object is non-null.

### Try / Catch and LastException (source, docs)

- `Catch` catches any exception; there is no typed catch (**docs**, coreref).
- `LastException` is the innermost cause of the caught exception
  ([`BA.setLastException`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L403-L407)).
  `LastException.Message` is the exception's Java `toString()`, not its
  `getMessage()` ([`B4AException.getMessage`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/objects/B4AException.java#L40-L42)):
  the class name, then `": "` and the message if there is one, for example
  `java.lang.RuntimeException: Object should first be initialized (List).`.
  A program that logs it puts that text on stdout. Messages that come from the
  JDK itself (index errors, parse errors) depend on the JDK version: **open**.

### Operators and precedence (docs, forum, open)

- Arithmetic: `*`, `/`, `Mod` bind tighter than `+`, `-` (**docs**, booklet §4.1.1).
  There is no power operator: `Power(x, y)` is a function.
- Relational: `=`, `<>`, `<`, `>`, `<=`, `>=` (**docs**). A user-posted table
  puts comparisons below arithmetic
  ([forum](https://b4x.com/android/forum/threads/x-y-mod-x-solved.120609/)).
- `And`, `Or` are boolean and **short-circuit**, left to right (**docs**,
  booklet §4.3.1.1). `Not` is a function, `Not(x)`, not a prefix operator
  (**docs**). Bitwise operations are `Bit.And`, `Bit.Or`, … functions.
- `&` concatenates; `+` is arithmetic only (**forum**). Precedence of `&`
  relative to `+` and to comparisons is **open**. B4J 10.70 refuses
  `"x" & 1 + 2` as a syntax error (**recorded**); the probe tests
  `concat_*` are to settle the rule. Earlier evidence:
  `"This " & 2 + 2 & " is a test"` being rejected in 2011 while
  `"This " & (2 + 2) & ...` works
  ([forum](https://www.b4x.com/android/forum/threads/bug-concatenating-strings.8701/)),
  which does not determine the order. Needs a recorded test.
- In a statement `x = a = b`, the first `=` is the assignment and the rest is
  one comparison (**generated**): `BluetoothState = NewState = Admin.STATE_ON`
  compiles to `_bluetoothstate = _newstate==_admin.STATE_ON;`. No source shows
  a real chain such as `a < b < c` or `If a = b = c`: **open**.
- The relative precedence of `And` versus `Or`, and of both versus comparisons,
  is not stated in official docs (**open**). The user table above
  contradicts common practice and is not reliable.

### Division (forum, Erel)

`/` always performs floating-point division, even between two `Int`s:
`55 / 10` is `5.5`; assigning it to an `Int` truncates it to `5`
([forum, Erel](https://www.b4x.com/android/forum/threads/interger-division.38133/),
[forum](https://www.b4x.com/android/forum/threads/how-to-do-division-of-two-ints-as-integer-division-instead-of-floating-point-division.158469/)).
The booklet's `$0.3{10 / 7}` → `1.429` agrees. Integer division is
`Floor(a / b)`. Division by zero in Double is not an error (`Infinity`/`NaN`;
[forum](https://www.b4x.com/android/forum/threads/divide-by-zero-not-an-error.142795/)).
**open**: the exact rule for converting a Double back to `Int`
(truncation toward zero is Java's `(int)` cast, as reported on the forum).

### Statements

- **`:`** separates statements on one line, exactly like a line break. So
  `If b = 0 Then a = 0 : c = 1` puts only `a = 0` under the `If`; `c = 1`
  always runs (**docs**, booklet §4.3.1). `Sub` and `End Sub` cannot share a line.
- **`Select`**: written `Select expr`, not `Select Case expr`
  ([forum](https://www.b4x.com/android/forum/threads/select-case-help.42378/));
  whether `Select Case` is a compile error is **open**. `Case` takes a
  comma-separated list of expressions; ranges (`Case 1 To 4`) are not
  supported (**docs**, booklet §4.3.3; Erel on the
  [forum](https://www.b4x.com/android/forum/threads/using-to-in-select-cases.137312/)).
  `Select True` with `Case x < 16` is the idiom for conditions. Matching:
  numbers compare as `double`, other values with `equals`
  ([`BA.switchObjectToInt`](https://github.com/AnywhereSoftware/B4J/blob/e26e645a611dd24c2034fbbeaf11ba26b70dee8b/jCore/src/anywheresoftware/b4a/BA.java#L514-L533),
  **source**; that the compiler uses it is **forum** level).
- **`Exit`** leaves the innermost loop; **inside a `Select` block it leaves the
  `Select`** (**docs**, coreref). `Continue` goes to the next iteration of the
  innermost loop (**docs**).
- **`Do`**: only `Do While cond … Loop` and `Do Until cond … Loop`. `Loop While`,
  `Loop Until` and a bare `Do … Loop` are not supported (**docs**, booklet
  §4.4.3; Erel on the [forum](https://www.b4x.com/android/forum/threads/while-or-until-at-end-of-do-loop-bug-wish.49474/)).
  Infinite loops are written `Do While True`.
- **`For`**: `For i = a To b [Step s]`. If the variable was not declared it
  is implicitly declared as `Int` (**docs**, coreref). Test is `i <= b` for a
  positive step and `i >= b` for a negative step. **open**: whether `b` and
  `s` are evaluated once (expected, as in VB), and the value of `i` after the loop.
- **`If`**: single line `If c Then stmt [Else stmt]`; block form with
  `Else If` (two words) (**docs**).
- **`IIf(cond, a, b)`** exists in current versions and evaluates only the chosen
  branch (**docs**, booklet §4.3.2). Not in the Level 0 grammar yet.

### Declarations and scope

- `Dim` is kept for compatibility; `Private` / `Public` are preferred
  (**docs**). In a Sub, all three declare a local.
- **Shared type**: `Private i, j, k As Int` declares all three as `Int`
  (**docs**, booklet §2.3.1).
- **Initialiser before `As`**: `Dim a = 1, b = 2, c = 3 As Int` and
  `Private txt = "test" As String, value = 1.05 As Double` are valid
  (**docs**, booklet §2.3.1 and coreref). The form `Dim x As Int = 5` is valid too.
- **Scope**: a variable declared anywhere in a Sub (including inside an `If`
  or loop) is visible in the whole Sub; the declaration is hoisted to the top
  of the Sub, and re-executing the `Dim` resets the variable to its default or
  initial value. For object types it creates a new instance
  ([forum](https://www.b4x.com/android/forum/threads/best-coding.108735/),
  [forum](https://www.b4x.com/android/forum/threads/easy-dim.20927/)).
  **forum** level; needs a recorded test.
- Primitives (numbers, `Boolean`, `Char`) are passed by value; everything else,
  including `String` and arrays, by reference copy (**docs**, booklet §2.1).
- Local variables get their default value on every call (**docs**, booklet §2.6.3).
- Undeclared non-loop variables: the forum says they default to `String`, with
  an IDE warning
  ([forum](https://www.b4x.com/android/forum/threads/can-you-use-a-variable-without-declaring.27855/)).
  **open**; current compilers may reject them.

### Keywords used as names (generated)

`In` is accepted as a name: B4X's `AsyncStreamsText` class declares a
parameter `In As InputStream` and calls `astreams.Initialize(In, out, ...)`,
compiled to `_in` in the generated Java. Which other keywords are contextual
in the same way is **open**.

### Types (docs)

Ranges in booklet §2.1 match the table in [spec/level0.md](../spec/level0.md#types)
(Java primitives). B4R differs (Int is 16-bit, Double is 32-bit) and is
out of scope for Level 0.

## Impact on the Level 0 spec

Applied to [spec/level0.ebnf](../spec/level0.ebnf), [spec/level0.md](../spec/level0.md),
[spec/level0-builtins.md](../spec/level0-builtins.md) and the conformance tests:

1. `level0.ebnf`:
   - add `:` as a statement separator;
   - allow `IDENT [= expr]` declarators sharing a final `As type`;
   - drop the `[ "Case" ]` after `Select` until a recording settles it;
   - leave `Not` as an ordinary function call, not a primary;
   - add `IIf`.
2. `level0.md`: replace "(to verify)" on scope with the hoisting rule; add `/`
   always Double; document `Exit` inside `Select`.
3. Runtime spec: `NumberToString`, `ObjectToString`, `NumberFormat`, smart
   string formatters, `Map` insertion order and key equality, `List` and the
   uninitialised-object error, as above.
4. New pending tests: precedence of `&`, `And`/`Or`, `Exit` inside `Select`
   inside a loop, `Dim` inside a loop, Float-to-string, Double formatting edge
   cases (`1e7`, `0.001`, `-0.0`), `/` between Ints assigned to Int.
